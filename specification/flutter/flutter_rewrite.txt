I checked the repository. LibreCrate on GitHub

LibreCrate is an open-source, offline encrypted document vault. The current repository README identifies version 0.5.5 and supports Android plus Linux/macOS/Windows desktop and CLI. 
G
GitHub

What it does
Stores PDF, EPUB, PKPass, CBZ comics, images, and Markdown notes.
Encrypts files at rest with AES-256-GCM.
Uses Argon2id for password-based key derivation and AES-256 Key Wrap for the master key.
Has zero network access, according to the project documentation.
Provides full-text search using FTS5.
Supports encrypted backups that can be moved between Android and desktop.
Android uses Jetpack Compose; the desktop application is written with Iced/Rust.
The core vault/crypto/database functionality is implemented in Rust and connected to Android through UniFFI.

Architecture

The repository is particularly interesting if you're looking at the code rather than just using the app:

LibreCrate
├── app/                  # Android app
├── vault-native/
│   ├── core/             # Rust vault, crypto, DB, backup, merge
│   ├── cli/              # CLI / REPL
│   └── gui/              # Iced desktop GUI
├── vault-reader/
├── reader-epub/
├── vault-native-android/
└── specification/


The Android build automatically builds the Rust native library through UniFFI.

The target architecture

I'd move toward:

                 Dart API layer
                       │
                 FFI / UniFFI

              │  LibreCrate     │
              │  Rust Core      │
              ├─────────────────┤

The important thing is that Flutter doesn't become the new core.

The existing project already has the core separated from the UIs, which makes this much less painful than starting from scratch.

The interesting part: readers

This is where I wouldn't blindly port the Android implementation.

LibreCrate currently has several different viewers—MuPDF for PDFs, Readium for EPUB, CBZ rendering, PKPass rendering, image viewing and Markdown editing.
G
GitHub

I'd make the Rust core responsible for:

encrypted file
      ↓
decrypt
      ↓
document abstraction
      ↓
Flutter reader


rather than making Rust draw the actual UI.

For example:

PdfReader(
  document: document,
  initialPage: document.lastReadPage,
);


The reader can then request decrypted data/pages through the native layer.

One architectural decision I'd make early

I'd introduce a clean application API between Flutter and Rust.

Something along these lines:

Flutter
   │
   │  createVault()
   │  unlockVault()
   │  listDocuments()
   │  search()
   │  importDocument()
   │  deleteDocument()
   │  backup()
   │  restore()
   │
   ▼
LibreCrate API
   │
   ▼
Rust Core


Don't expose your entire Rust internal object graph to Dart.

That's going to make the project dramatically easier to evolve.

And I'd make the API async

Because operations like importing a 500 MB PDF, extracting text, indexing it, creating a backup, or restoring a vault shouldn't block the Flutter UI.

Conceptually:

final result = await vault.importFile(path);


rather than exposing synchronous operations that tie up the UI thread.

One thing I would not do

I wouldn't start by creating a beautiful Flutter UI.

I'd start by proving this:

Flutter Android
       │
       ▼
     FFI
       │
       ▼
   Rust Core
       │
       ▼
existing LibreCrate vault


Then:

Create vault
Unlock vault
List documents
Import PDF
Read metadata
Search
Delete
Backup
Restore
Lock/unlock

If all of that works, then build the polished UI.

That lets you preserve compatibility with existing .librecrate vaults and backups while replacing the frontend.

My verdict

For this particular project, I'd actually change my earlier answer from "Flutter could make sense" to:

Yes, I think Flutter + Rust is probably the better long-term architecture for LibreCrate.

The current project is already halfway there. The Rust core is shared, while Compose and Iced are the two presentation layers.
G
GitHub

So the migration isn't really:

"Rewrite LibreCrate in Flutter."

It's:

"Replace two UI implementations with one Flutter UI while preserving the Rust vault engine."

That's a much more compelling proposition.
